# D2

Status: research. D2 (<https://d2lang.com>) is newer than the other languages and still
changing, so the work starts by pinning a reference version and checking the mapping below
against its parser tests.

## D2-1 Mapping to research

- Shapes and labels: `a`, `a: Label`, `a.shape: circle`, and D2's shapes, onto LANGS-3 and the
  flowchart shapes.
- Connections: `->`, `<-`, `<->`, `--`, chains, labels, `source-arrowhead` and
  `target-arrowhead` with their shapes.
- Containers: `a.b.c`, nested maps, and edges between containers, onto clusters.
- `direction`, `style.*` (fill, stroke, stroke-width, stroke-dash, font-color, opacity,
  border-radius), and `classes`.
- `sql_table` and `class` shapes onto compartments (LANGS-3).
- Text: Markdown and code labels (`|md ... |`), drawn as text at first.
- Comments, block strings, and escapes.

## D2-2 Open questions

- Which D2 version is the reference, and whether its parser tests can seed the fixture corpus
  (LANGS-6).
- Globs, `vars`, imports (`...@file`), and spread: which to support. Imports read other files, so
  they need the same care as PlantUML's `!include` (PUML-4).
- `near`, `grid-rows` and `grid-columns`, `width` and `height`, and `label.near`: these need
  layout constraints LAYOUT does not have.
- `layers`, `scenarios`, and `steps`: whether to draw the first board only or let the editor pick
  one, as it picks Markdown blocks (WYSIWY-20).
- Icons and images: never fetched; drawn as a placeholder or omitted.
- ELK and TALA layouts look different from D2's default dagre layout; matching dagre, as LAYOUT
  does, is the target.

The outcome is a `pending` spec in the shape of `graphviz-dot.md`.
